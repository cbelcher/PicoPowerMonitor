The short answer is no, it will not match both strings. While it works perfectly for the first string, it fails on the second one because of the negative sign in the current value.

"V: 0.000, I: 0.000, P: 0.000"	Yes					All values consist only of digits and

********************************************************************************
Why it Fails
********************************************************************************

In MicroPython (and standard Regex), [\d.] is a character set that matches only digits and literal periods. When the regex engine reaches the I component in your second string:

1. It matches I:\s*.

2. It looks for the first character of ([\d.]+).

3. It encounters -.

4. Since - is not a digit or a dot, the match fails immediately.

Code change (Option 1)
To make this regex robust enough to handle negative numbers, you need to include the hyphen in your character classes.

Recommended Regex:V:\s*([-?\d.]+),\s*I:\s*([-?\d.]+),\s*P:\s*([-?\d.]+)

[!TIP]
By adding -? inside the group or adding the hyphen to the set [\d.-], you allow the engine to capture the sign. In MicroPython's re module, [\d.-]+ is usually the most efficient way to capture a standard float representation.

Python
# This version handles positive and negative values
regex = r"V:\s*([\d.-]+),\s*I:\s*([\d.-]+),\s*P:\s*([\d.-]+)"

Quick Component Check:
• \s*: Handles any number of spaces (useful if your sensor output fluctuates).
• ([\d.-]+): Captures digits, dots, and hyphens.
• ,: Matches the literal comma separators in your string.

********************************************************************************

Option 2

Why the Second String Fails
The issue lies in how you are capturing the numbers with your character class: ([\d.]+).

• \d matches any digit (0-9).
• . matches a literal decimal point.
• + means "one or more" of these characters.

This pattern matches positive decimals like 0.000 or 1.698 perfectly. However, it does not match the minus sign (-) in -0.011. Because the regex engine encounters - right after I: , and - is not a digit or a dot, the match fails immediately.

The Solution
To make this regex match both positive and negative numbers, you need to allow an optional plus or minus sign ([-+]?) right before the digits.

The Corrected Regex
V:\s*([-+]?[\d.]+),\s*I:\s*([-+]?[\d.]+),\s*P:\s*([-+]?[\d.]+)

How it works:
• [-+]?: This searches for an optional - or + sign. The ? means "zero or one" occurrences.
• [\d.]+: Matches the rest of the float value (digits and the decimal point).

Python
import re

# The corrected regex pattern
pattern = r"V:\s*([-+]?[\d.]+),\s*I:\s*([-+]?[\d.]+),\s*P:\s*([-+]?[\d.]+)"

string1 = "V: 0.000, I: 0.000, P: 0.000"
string2 = "V: 1.698, I: -0.011, P: 0.010"

for s in (string1, string2):
    match = re.search(pattern, s)
    if match:
        v, i, p = match.groups()
        print(f"Matched -> V: {v}, I: {i}, P: {p}")
    else:
        print(f"Failed to match: {s}")
